# Validation Set (검증 데이터셋)

> **검증 데이터셋은 학습 중에 모델을 고르고 조율하기 위해 쓰는, 학습에는 넣지 않은 중간 점검용 데이터다.**

## 시험 전에 풀어보는 모의고사

실제 시험(테스트)을 보기 전, 실력을 점검하려고 모의고사를 푼다. 모의고사 결과를 보고 어느 단원을 더 공부할지, 전략을 어떻게 바꿀지 정한다. **검증 데이터셋이 바로 이 모의고사다.** 학습 데이터로 공부한 모델이 얼마나 하는지 검증셋으로 확인하고, 그 결과를 보며 하이퍼파라미터를 조정하거나 더 나은 모델을 고른다.

여기서 데이터가 셋으로 갈리는 이유가 나온다. **학습셋**으로 배우고, **검증셋**으로 튜닝하며, **테스트셋**으로 마지막에 딱 한 번 채점한다.

| 데이터셋 | 역할 | 몇 번 쓰나 |
|----------|------|-----------|
| 학습셋 | 모델이 파라미터를 배운다 | 매 학습마다 |
| 검증셋 | 하이퍼파라미터 튜닝·모델 선택 | 여러 번 반복 |
| 테스트셋 | 최종 일반화 성능 평가 | 마지막에 단 한 번 |

## 검증셋은 테스트셋을 지키기 위해 존재한다

핵심은 이것이다. **검증셋이 없으면 튜닝을 테스트셋으로 하게 되고, 그러면 테스트 점수를 더는 믿을 수 없게 된다.** 테스트 결과를 보고 모델을 고치는 순간 테스트셋이 간접적으로 학습에 개입하기 때문이다. 검증셋은 이 오염을 막는 방패다. 튜닝의 때는 검증셋이 다 뒤집어쓰고, 테스트셋은 깨끗하게 최종 평가용으로 남긴다.

검증셋은 [조기 종료](Early_Stopping.md)의 판단 기준으로도 쓰인다. 검증 오차가 다시 오르기 시작하면 과적합 신호로 보고 학습을 멈춘다.

> 💡 **참고 — 데이터가 적으면 검증셋 대신 교차 검증.**
>
> 데이터가 부족하면 고정된 검증셋을 떼는 것 자체가 아깝고, 어느 데이터가 검증셋이 되느냐에 따라 결과도 출렁인다. 이럴 땐 데이터를 여러 조각으로 나눠 돌아가며 검증하는 [교차 검증](CrossValidation.md)이 더 안정적이다.

## 흔한 오해

> ⚠️ **흔한 오해 — "검증셋과 테스트셋은 같은 것이다."**
>
> 둘 다 학습에 안 쓴다는 점은 같지만 역할이 다르다. 검증셋은 개발 중 **여러 번** 보며 모델을 고치는 데 쓰고, 테스트셋은 다 끝난 뒤 **단 한 번** 최종 성적을 매기는 데만 쓴다. 검증셋 성능은 튜닝하며 이미 낙관적으로 물들기 때문에, 진짜 실력은 테스트셋으로 재야 한다.

## 정리하면

- 검증 데이터셋은 학습 중 모델을 고르고 튜닝하기 위한 중간 점검용 데이터다.
- 데이터는 학습·검증·테스트 셋으로 갈리며 각자 역할이 다르다.
- 검증셋은 튜닝의 오염을 대신 뒤집어써 테스트셋을 깨끗하게 지킨다.
- 데이터가 적으면 고정 검증셋 대신 교차 검증을 쓴다.
