# Random Search (랜덤 서치)

> **랜덤 서치는 하이퍼파라미터 후보를 격자로 촘촘히 훑는 대신, 탐색 공간에서 무작위로 조합을 뽑아 평가하는 탐색 전략이다.**

## 넓은 방에서 물건을 찾는 두 가지 방법

넓은 방에서 잃어버린 물건을 찾는다고 하자. 한 방법은 바닥에 격자를 긋고 칸마다 빠짐없이 뒤지는 것이다([그리드 서치](Grid_Search.md)). 또 하나는 방 곳곳을 무작위로 찍어 뒤지는 것이다. 후자가 랜덤 서치다. **엉성해 보이지만, 정해진 시간 안에서는 오히려 이쪽이 자주 이긴다.**

이유는 이렇다. 하이퍼파라미터 여러 개 중 결과에 크게 영향을 주는 건 보통 한둘뿐이다. 그리드 서치는 중요치 않은 파라미터에도 똑같이 칸을 배정해 시간을 낭비하지만, 랜덤 서치는 무작위로 뽑기 때문에 **중요한 파라미터의 다양한 값을 훨씬 많이 밟아본다**(Bergstra & Bengio, 2012). 같은 시도 횟수라면 랜덤 서치가 더 넓게, 더 효율적으로 훑는다.

## 후보를 독립적으로 뽑아 각각 평가할 뿐이다

작동은 단순하다.

1. **탐색 공간 정의:** 각 하이퍼파라미터의 범위나 분포를 정한다(예: 학습률은 로그 스케일 구간, 트리 깊이는 3~15).
2. **무작위 추출:** 정해둔 시도 횟수만큼, 그 범위에서 조합을 **하나씩 독립적으로** 뽑는다.
3. **평가:** 각 조합으로 모델을 학습·검증해 성능을 잰다.
4. **선택:** 시도 예산을 다 쓰면, 평가한 것들 중 **가장 성능 좋았던 조합**을 고른다.

> ⚠️ **흔한 오해 — "이전에 좋았던 조합 근처에서 다음 샘플을 뽑는다."**
>
> 그건 랜덤 서치가 아니라 [베이지안 최적화](Bayesian_Optimization.md)나 진화 알고리즘이 하는 일이다. 순수 랜덤 서치의 각 샘플은 **이전 결과와 무관하게 독립적으로** 뽑힌다. 과거를 참고하지 않기 때문에 병렬 실행이 쉽고 구현도 간단하지만, 좋은 영역을 찾아 파고드는 능력은 없다.

## 그리드 서치와 어떻게 다른가

| | 그리드 서치 | 랜덤 서치 |
|---|---|---|
| 후보 선택 | 모든 격자 조합을 전부 | 정해진 횟수만큼 무작위로 |
| 차원이 늘 때 | 조합 수가 폭발(조합 폭발) | 시도 횟수를 내가 고정 |
| 중요 파라미터 탐색 | 값 종류가 격자에 묶임 | 훨씬 다양한 값을 밟음 |
| 예산 조절 | 어려움 | 시도 횟수로 자유롭게 |

## 정리하면

- 랜덤 서치는 탐색 공간에서 **조합을 무작위·독립적으로 뽑아** 평가한다.
- 각 샘플이 과거와 무관하므로 **구현이 쉽고 병렬화가 자연스럽다.**
- 중요한 소수 파라미터를 더 다양하게 밟아, **같은 예산이면 그리드 서치보다 효율적인 경우가 많다.**
- 최적해를 보장하진 않고, 좋은 영역을 지능적으로 파고들지도 못한다.
