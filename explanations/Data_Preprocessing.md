# Data Preprocessing (데이터 전처리)

> **데이터 전처리는 지저분하고 제각각인 원본 데이터를 모델이 먹을 수 있는 깨끗한 형태로 다듬는 과정이다.**

## 요리 전 재료 손질과 같다

좋은 요리는 칼을 들기 전 재료 손질에서 갈린다. 흙 묻은 채소를 씻고, 상한 부분을 도려내고, 크기를 맞춰 썰어야 불에 올릴 수 있다. **데이터 전처리가 바로 이 손질 단계다.** 현실의 데이터는 값이 비어 있고, 오타가 섞이고, 단위가 제각각이고, 형식이 뒤죽박죽인 채로 도착한다. 이걸 그대로 모델에 넣으면 결과도 그만큼 엉망이 된다. "쓰레기를 넣으면 쓰레기가 나온다(garbage in, garbage out)"는 말이 여기서 나온다.

전처리는 화려하지 않지만, 실제 머신러닝 프로젝트에서 **시간의 절반 이상**을 잡아먹는 곳이다. 모델을 바꾸는 것보다 데이터를 제대로 손질하는 쪽이 성능을 더 크게 끌어올릴 때가 많다.

## 결측·이상·스케일·형식, 네 가지를 손본다

전처리에서 손대는 문제는 대체로 넷으로 나뉜다.

| 문제 | 무엇이 잘못됐나 | 흔한 처리 |
|------|----------------|-----------|
| 결측값 | 값이 비어 있다 | 평균·중앙값으로 채우거나, 그 행/열을 버린다 |
| 이상치 | 값이 비상식적으로 튄다 | 잘라내거나(clipping) 변환하거나 별도 검토한다 |
| 스케일 차이 | 변수마다 단위·범위가 다르다 | 정규화(0~1)·표준화(평균 0, 분산 1)로 맞춘다 |
| 형식·타입 | 문자열, 범주형이 섞여 있다 | 인코딩(원-핫 등)으로 숫자로 바꾼다 |

특히 **스케일 맞추기**는 거리나 기울기에 민감한 알고리즘(경사 하강법 기반 신경망, 최근접 이웃, SVM 등)에서 성능을 크게 좌우한다. 나이(0~100)와 연봉(0~1억)을 그대로 두면 연봉의 큰 숫자가 학습을 지배해 버린다.

## 흔한 오해

> ⚠️ **흔한 오해 — "전처리는 데이터 전체에 한 번 해두면 된다."**
>
> 스케일링 같은 변환의 기준(평균·표준편차 등)은 **학습 데이터에서만** 계산해야 한다. 테스트 데이터까지 포함해 계산하면 미래 정보가 학습에 새어 들어가는 [데이터 누수](Data_Leakage.md)가 생겨, 실제보다 성능이 부풀려 보인다. 분할을 먼저 하고, 학습 데이터로 익힌 기준을 테스트 데이터에 그대로 적용한다.

## 정리하면

- 데이터 전처리는 원본 데이터를 **모델이 쓸 수 있는 깨끗한 형태**로 다듬는 과정이다.
- 결측값·이상치·스케일 차이·형식 문제, 이 네 가지를 주로 손본다.
- 스케일링과 인코딩 같은 변환은 **학습 데이터 기준으로만** 계산해 누수를 막는다.
- 모델 교체보다 데이터 손질이 성능을 더 끌어올리는 경우가 흔하다.
